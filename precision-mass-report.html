1. frappe.db.commit() inside a doc_events hook (11 location(s))

ACTION REQUIRED · Rule: v16-db-commit-in-doc-events · [silent, T-30]

Why it matters: A function registered in doc_events calls frappe.db.commit(). v16 turns transaction control off while document hooks run, so the commit only prints a warning and is ignored. Anything the code relied on being saved at that point stays in the open transaction and is rolled back if the request fails later.

Suggested action: Remove the commit and let the request commit at the end. If the data must survive a failure, write it in a separate background job (frappe.enqueue).

5. SQL written as a string in get_all / get_list fields or filters (4 location(s))

ACTION REQUIRED · Rule: v16-get-all-sql-strings · [quiet, T-30]

Why it matters: frappe.get_all / get_list in v16 accept only plain field names in `fields` and plain field names as filter keys. SQL written as a string (sum(x) as y, distinct x, ifnull(...), a quoted literal) raises a ValidationError when the query runs.

Suggested action: Use the dict syntax for SQL functions, for example {"COUNT": "*"}, or frappe.qb for a complex query. In filters, filter on a plain field name.
